# Stay Automatic quiz + full redesign brief

Date: 2026-07-29

## New strategic correction from Kyle

The previous distilled line was wrong. `Own your operating layer. Rent the models.` sounds abstract, MBA-ish, and not emotionally useful. It also over-centers models when the actual sell is closer to: **a computer/operator you control, powered by frontier models when useful, with a community/workflow library around it.**

The offer should be less “AI strategy guide” and more:

> Get your own AI operator running on a real cloud computer, connected to the tools you choose, using the best frontier models without being trapped inside any one chat app or SaaS wrapper.

Important tone shift:
- More anti-SaaS-sprawl / anti-wrapper / anti-overengineering.
- Less timid “pick the right tool” language.
- Still honest: sometimes ChatGPT/Claude alone is enough.
- But the quiz should lead people toward understanding **why owning a full operator is different from renting another AI SaaS layer**.

## Competitor rethink

### True competitors

1. **Frontier model companies** — OpenAI, Anthropic, Google, Microsoft.
   - They have the model quality, brand trust, and native connectors.
   - They may eventually ship a better built-in harness.
   - For now, their advantage is UX and distribution.
   - Their weakness is that the user’s workflows live inside their product boundaries.

2. **Managed AI agent products** — Lindy, Gumloop, Relevance, MindStudio, Agent.ai, Manus.
   - They may look like competitors, but the stronger critique is that many become another SaaS layer between the user and frontier models.
   - Some are useful; many are likely overengineering for people who could use Hermes + frontier models directly.

3. **Open-source/self-host tools** — Dify, OpenWebUI, n8n, Flowise, etc.
   - These need plain-English explanation, but probably should not dominate the page.
   - Position them as alternate tool classes / comparison content, not core threats.

### The stronger Stay Automatic position

Stay Automatic should not say “we are not with those tools.” It should say:

> Use the best frontier models. But don’t let your actual work get trapped inside one model company’s chat window or one SaaS wrapper’s pricing page.

## Product shape

### Core product

A paid guide / setup kit that helps someone set up:
- Hermes Agent.
- Hermes Portal/cloud/VPS path, framed as a low-cost always-on AI work computer.
- Telegram or preferred messaging channel.
- model/provider access.
- safe app connections.
- first workflow.
- skill/workflow library access.
- community support.

### Community / repo layer

This is important and should move up in the offer.

When someone buys, they are not only buying a PDF. They get access to:
- a curated repository of small-business skills and workflow ideas,
- tried-and-true starter automations,
- role/industry playbooks,
- community discussion around what actually works,
- updates as frontier models and Hermes capabilities improve.

This makes the product defensible even if setup instructions are copy/paste. The value compounds through the workflow library and community.

## Quiz concept: AI Operator Fit Check

The quiz should feel like a smart agent conversation, not a dumb Typeform.

### Name options

- **AI Operator Fit Check**
- **Workflow Leak Quiz**
- **Own Your Operator Quiz**
- **AI Work Computer Finder**
- **Stay Automatic Setup Diagnostic**

### Strongest name for now

**AI Operator Fit Check**

It is clearer than “workflow leak” if the site is now about owning an operator.

### Quiz posture

The quiz should always teach the user why this matters, even before the result.

It should ask questions like:
1. Where does work pile up?
2. What tools does the work touch?
3. Does it need to happen repeatedly?
4. Does it need judgment or just routing?
5. Would you trust AI to draft it, or only prepare it for approval?
6. Does the work need files, browser actions, email, calendar, docs, spreadsheets, or code?
7. Do you want this to live inside ChatGPT/Claude, or on a small cloud computer you control?
8. How comfortable are you with copy/paste setup versus guided help?
9. What kind of work do you do?
10. What do you do for fun / outside work? This helps generate personal AI use cases too, not just work automations.

### Output paths

1. **Frontier-chat only**
   - “Start with ChatGPT/Claude/Gemini. You do not need a full operator yet.”

2. **Simple automation**
   - “Use Zapier/n8n/Make for this one fixed handoff.”

3. **Operator-ready**
   - “You have repeated work across apps. A Hermes-style operator makes sense.”

4. **Setup-call recommended**
   - “This touches customer messages/money/public claims/regulated work. Do not automate blindly.”

5. **Not ready yet**
   - “Your process needs to be written down before AI will help.”

### Important: biased but honest

The quiz can point toward Hermes/operator ownership more often than a neutral survey would, because that is the product thesis. But it must still earn trust by sometimes saying “don’t buy this yet.”

## Website redesign direction

Kyle’s read is right: current site risks feeling like a 2010s Silicon Valley startup / generic AI agency page. The next design should feel like:

- premium practical command center,
- owned cloud workbench,
- field manual / operator desk,
- small-business trust,
- anti-wrapper, anti-hype,
- not cyberpunk slop,
- not bubbly SaaS cards.

### Visual metaphor

**A cloud computer / operator desk.**

Hero idea:
- User messages from Telegram / email / browser flow into a small 3D “work computer.”
- Frontier models orbit as engines, not the product.
- Skills/workflows appear as physical cards/modules inserted into the operator.
- The user owns the box; models are swappable power sources.

### Motion ideas

- Scroll-driven camera through layers:
  1. Chat window / human request.
  2. Cloud computer / Hermes operator.
  3. Frontier model engines.
  4. Tools: Gmail, Calendar, Drive, browser, files, web, code.
  5. Skills/workflows library.
  6. Human approval gate.
  7. Finished work returned.

- As the user scrolls, each layer locks/pins and reveals a single idea.
- Avoid random particles unless they mean something.
- 3D should explain ownership, not just decorate.

## Skill stack research

### Best Hermes skill for overall redesign

**Use `claude-design` as the main skill.**

Reason:
- It is the design-process skill.
- It explicitly supports repo redesigns, marketing pages, motion studies, local artifact verification, and anti-slop rules.
- It tells the agent to inspect actual repo files, build in the stack, run build, open browser, check console, and QA.

### Best skill for early variants

**Use `sketch` before committing production code.**

Reason:
- The user wants a full aesthetic reset.
- We need 2–3 different design stances, not one premature production rewrite.
- Sketch can create throwaway HTML variants fast and verify visually.

Recommended variants:
1. **Owned Operator Desk** — premium editorial + 3D cloud computer metaphor.
2. **Anti-SaaS Field Manual** — sharp black/cream editorial, more manifesto-driven.
3. **Community Workflow Library** — warmer, more human/community, skill cards and repository metaphor.

### Best skill for 3D / generative visuals

**Use `p5js` for custom generative/canvas/WebGL motion studies, especially if we want visual concepts before adding heavy React deps.**

Reason:
- It supports WebGL, shaders, particles, interactive browser visuals, export, and verification.
- It is good for developing the hero visual language quickly.

For production React 3D, use libraries directly:
- `three`
- `@react-three/fiber`
- `@react-three/drei`
- optionally `@react-three/postprocessing`

### Best skill for text-driven / editorial kinetic effects

**Use `pretext` selectively.**

Reason:
- Could create a killer “AI wrappers / SaaS slop / actual work” kinetic typography section.
- Good for text flowing around a 3D operator box or shattering SaaS buzzwords into workflow cards.
- Do not use for the whole site; use for one memorable section if needed.

### Best existing design-system reference skill

**Use `popular-web-designs`, but do not copy Stripe/Linear/Vercel directly.**

Useful templates to borrow principles from:
- `linear.app.md` — precision, dark minimal, serious product taste.
- `vercel.md` — sharp monochrome, developer trust, clean primitives.
- `apple.md` — scroll-driven product storytelling and restraint.
- `stripe.md` — premium gradients if used carefully, but avoid generic startup feel.
- `superhuman.md` or `raycast.md` — operator/productivity feel.
- `voltagent.md` / `opencode.ai.md` — terminal-native energy if we want darker developer credibility.

### External frontend stack recommendation

Current repo is Vite + React + CSS only. For the redesign, install only what earns its place.

Recommended production stack:
- **React + Vite** existing.
- **GSAP + ScrollTrigger** for complex scroll narratives and pinned sections.
- **Lenis** for smooth scroll and scroll-trigger sync.
- **Three.js + React Three Fiber + Drei** for the 3D operator/cloud-computer hero.
- Optional **Motion** only if we need component micro-interactions; avoid mixing too many animation systems.

Do not start with Spline. Spline is fast, but it creates another design-tool dependency. Since the brand thesis is ownership, code-owned R3F is philosophically cleaner.
